# 第一次代码练习：为什么旧页面收到 409

目标：能亲自复现一个真实行为，并用自己的话说明它保护了什么。

## 先观察

1. 启动工作台，在两个浏览器页面打开同一地址。
2. 在页面 A 修改重点并保存。
3. 在尚未刷新的页面 B 修改重点并保存。
4. 观察页面 B 的提示。回到页面 A 刷新，确认已保存的内容仍在。

只用临时测试内容，不用自己重要的工作数据。练习前可先导出备份。

## 再读三处代码

- app.js 的 persist：发送当前快照和 revision，保存失败时显示服务器提示。
- server.py 的 do_POST：在锁内比较 candidate 与 current 的 revision。
- test_server.py 的 test_stale_save_returns_conflict_without_overwriting：模拟两个页面，检查旧版本写入被拒绝。

运行这个测试：

~~~bash
python3 -m unittest -v test_server.ServerTest.test_stale_save_returns_conflict_without_overwriting
~~~

## 自己解释

- 两个页面起初为什么拿到同一个版本号？
- 页面 A 保存后，磁盘上的版本号发生了什么变化？
- 为什么不能让页面 B 直接覆盖？
- 409 和 400、403 分别表示哪类问题？

参考：400 表示请求的数据不符合要求；403 表示请求不符合访问检查；409 表示请求基于旧版本，与当前状态冲突。
